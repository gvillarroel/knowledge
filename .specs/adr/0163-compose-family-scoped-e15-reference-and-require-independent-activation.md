# ADR 0163: Compose the E15 reference by family and require independent activation

Status: Accepted for preparation only. E15 development remains blocked until
the independent review, exclusive private custody, organizer design seal and
development-stage transition all pass against the prepared source digests.

Date: 2026-09-13.

## Context

E15 must eventually compare one coherent eight-family skill bundle. Six family
references come from terminal E14 winners. Entity Graph and Ensemble instead
have prospective construction candidates that passed bounded software checks
but have no qualified full-workload retrieval measurement. Copying any one
complete candidate tree would silently replace unrelated family implementations
or retrieval profiles with that candidate's ancestry.

The Ensemble candidate also contains Entity Graph files inherited during its
realization. Those files are outside the Ensemble mutation scope and differ from
the separately prepared Entity Graph candidate. Treating that ancestry as the
Entity Graph source would erase the explicit candidate boundary.

The E15 execution design also needed an executable controller, exact derived job
configurations, source verification and a native owner preflight before an
independent reviewer could assess a concrete implementation.

## Decision

Build the prospective E15 qualification reference from one digest-bound source
per family. Transfer each family's complete `assets/families/<family>` subtree
and its exact `assets/retrieval-profile.json` entry. Use the six terminal E14
winners for Legacy, Turso, Adaptive, Embeddings, Classical and Graphify; use the
Entity bounded-selection candidate for Entity Graph; and use the Ensemble
mention-automaton candidate for Ensemble.

Ignore and explicitly record candidate drift outside the family being
transferred. In particular, the Ensemble candidate's inherited Entity Graph
files cannot enter the composed reference. Entity Graph comes only from its own
sealed candidate. Reject any unlisted cross-family drift, missing profile entry,
changed source tree or changed runtime source digest.

Treat this composed tree as a prospective qualification reference. It has no
fitness until both reserved first measurements qualify and the paired joint
development replay reproduces all eight family scores. A first measurement
establishes a family reference; it cannot be counted as a gain against an E14
attempt that produced no score.

Use the E15 controller's exact rules: one attempt and zero retries for each
reserved first-measurement identity, no reissue of consumed E14 identities,
three consecutive unique evaluable misses per mechanism, duplicate proposals
skipped without charge, and a five-round family ceiling. At most two native jobs
may be active globally.

Derive four exact Harbor configurations for the two first measurements, joint
development replay and all-500 recalculation. Require each derived job signature
to match its E14 source after normalizing only the job name, job directory and
skill path. Run owner `--dry-run` and `--doctor` modes for all four configurations
without dispatching native trials.

The executable preflight does not activate E15. A future execution contract must
bind every current source and preparation digest, identify a new independent
review, establish exclusive private custody, verify the organizer design seal,
and name the currently running stage. The admission check must run before every
native allocation and fail closed if any binding changes.

## Consequences

The prepared reference contains 252 files in 78 directories and has tree digest
`sha256:3e0c9d4628d2e34f5fda3203c1d663ca0eb874b5f322942bc42d20ba5abc3651`.
Eighteen focused tests passed. Native owner dry-run and doctor checks passed for
all four configurations across both modes. The final verification receipt is
`sha256:00a2553766f61e399df726158590c0ff6f6d4248e108060d7d42e74056ed0237`.

The first local preparation stopped before composition because its verifier
incorrectly treated an order-independent profile map as ordered. A corrected
preflight then passed, but was superseded before activation when the explicit
admission verifier and live two-family adapter were added. Both paths remain
preserved and are non-reusable. Neither path dispatched a native trial, called a
model or released validation.

The [executable preflight report](../../evaluations/reports/evolution/e15/executable-preflight-001/README.md)
publishes only aggregate, source-bound evidence. Runtime sources, composed skill
trees, logs, registrations and private datasets remain ignored. No new
EnterpriseRAG score, family qualification, quality miss, joint comparison,
all-500 result, independent acceptance, public rank or promotion is claimed.
