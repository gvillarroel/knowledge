# ADR 0132: Qualify a versioned Graphify builder before consultation evolution

Date: 2026-09-09

Status: Accepted for prospective preparation. Native execution requires terminal
predecessors, the exact fixed protocol, independent review and design sealing.

## Context

The original E8 Graphify baseline exceeded its 2,400-second first-build limit.
It has no retrieval reward or complete reference artifact. A public synthetic
audit identified repeated scans of all pair scores inside neighbor selection.
The isolated replacement preserved ordered edge tuples on the tested fixtures;
its host timing ratio does not establish complete-build or retrieval performance.

A complete builder-only candidate now changes exactly that function in one
packaged asset. The realizer verified the original parent, the exact diff and
150 synthetic edge comparisons. Construction feasibility and complete artifact
parity remain unmeasured. E8's sealed controls and remaining native search are
unchanged, as required by [ADR 0131](0131-correct-sealed-enterprise-admission-prospectively.md).

## Decision

Use a separate fixed, public feasibility study before selecting the reference
for the next consultation study. Freeze one complete candidate and the original
consultant before the feasibility seal. Its ordinary evaluation stage is owned
by `harbor-run-results`; it does not perform adaptive builder selection, private
acceptance or promotion. A failed required cell stops this fixed design. Any
revised builder requires a separately declared treatment and study.

Before native execution, require independently reviewed public artifact-parity
fixtures, deterministic rebuilds, unchanged graph and query semantics, and
negative checks that still reject invalid artifacts. Keep the original
implementation as a correctness reference on fixtures it can complete. Define
allowed metadata differences prospectively. The modified function cannot be its
own sole correctness oracle.

The native feasibility allocation is one candidate trial on the unchanged
Graphify 120-question, 6,000-document task, with one attempt and zero retries.
Keep the original two-CPU, 6-GiB, network-isolated environment, model cache,
agent profile, 3,600-second adapter limit and 2,400-second builder subprocess
limit. Require both independent builds, all original validation gates, every
declared query route, finite rewards, evidence integrity 1 and zero execution
errors. Qualification establishes development feasibility for this exact
package; it supplies no original-versus-new native speed ratio or quality gain.

After feasibility succeeds, seal a separate optimization study whose explicitly
versioned Graphify reference contains the qualified builder and original
consultant. Its selected Graphify treatment must use that same frozen builder.
Carry all historical proposals, native attempts, failed construction costs,
miss counters, catalog rounds and permanent unavailable profiles forward.
Account for the additional feasibility trial and any necessary reference
requalification separately; changing a study or package never resets budgets.

Changing an asset in the aggregate bundle changes its complete installed
identity. Keep historical jobs bound to their actual packages. Do not relabel
them as observations of the revised reference. Require new native qualification
or replay wherever the owning provenance contract requires it.

Retain all-eight development replay, one exact merged selection, the paired
all-500 retrieval comparison and the two-source, all-eight, 32-trial one-way
acceptance gate. Both Graphify arms in those comparisons use the new reference
builder. The comparison therefore measures consultation changes relative to
that version; it cannot isolate quality non-regression or construction benefits
against the unmeasured original. Every mandatory pair must qualify. Missing
fitness remains missing, and final all-500 results cannot alter selection.

Keep the private portfolio unopened throughout feasibility. A fresh independent
review must verify terminal predecessors, complete exposure history, unchanged
non-consumption and exclusive custody before optimization. Preparation outside
a formal study is permissible while E8 runs; a competing registry or native
execution is not.

## Evidence and consequences

The [original native failure](../../evaluations/reports/evolution/e8/graphify-baseline-failure-001/README.md),
[synthetic scaling audit](../../evaluations/reports/evolution/e8/graphify-scaling-001/README.md)
and [sealed candidate preparation](../../evaluations/reports/evolution/e8/graphify-candidate-001/README.md)
preserve the distinct evidence levels. Independent methodology advice is bound
in E8's append-only ledger, with assessment SHA-256
`d974f803cca25a32c1184f0e32d28e606cbb9a2283d25e65f85dd1d3042c64e9`.

This versioned reference makes a useful complete comparison possible if every
required gate passes. It changes the reference question prospectively; it does
not repair, complete or rewrite the original failed Graphify baseline.
