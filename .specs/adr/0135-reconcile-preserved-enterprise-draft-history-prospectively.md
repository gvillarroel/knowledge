# ADR 0135: Reconcile preserved Enterprise draft history prospectively

Date: 2026-09-09

Status: Proposed. The implementation requires independent review before fixed
public registration, followed by the actual design seal and current admission.

## Context

The final E8 history audit retained ten registry directory identities. Nine
passed the maintained organizer's current deep source verification. One
unsealed, never-started E6 preparation registry locks source locations that now
contain the later executed E6 dataset version. Its unchanged registered source
pointers therefore fail verification. Both complete original preparation
snapshots remain preserved separately and match every original locked task and
all 192 files in the original authoring inventory.

The executed E6 registry independently verifies at its original sources.
Restoring the old bytes there would invalidate that executed history. Editing
the old preparation locks would rewrite evidence. The organizer has no built-in
retirement or source-substitution operation. Caller002 correctly refuses this
combination; the prospective retirement sidecar does not waive that refusal.

## Decision

Prepare a separate caller version with one explicit historical reconciliation
for the exact retired preparation registry, frozen study and ledger hashes,
lock hashes, original preserved source locations and known current source
version. This reconciles historical accounting only. The old registered source
still fails its deep check, and the old draft receives no execution authority.

Require the unchanged organizer to verify the original ledger and locks. Require
only initialization, dataset registration and stage addition events, all stages
planned, no seal, no evidence and no private release. Reproduce the exact known
current-source refusal. Verify both preserved complete trees and the complete
discovered task inventories against the original locks using the maintained
organizer's hashing and discovery functions. Hash private bytes mechanically
without parsing or exposing private task contents.

Bind the known current shared-source version to the separately deep-verified
executed E6 registry and its terminal execution history. Require the exact
independent retirement sidecar and a separately reviewed reconciliation binding
in the future admission. Check that the retired draft's declared native paths
remain absent. A name, planned status, copied snapshot or retirement declaration
alone cannot qualify another registry for this handling.

Keep ordinary deep verification unchanged for every other predecessor. Preserve
all original sources, ledgers, reviews, refusals, preparations, costs, exposures,
unavailable profiles, pending claims, counters and catalog limits. Preserve the
complete current process and mount exclusion checks. Do not modify the maintained
organizer or substitute any original dataset source in memory or on disk.

The fixed Graphify task, candidate, native configuration, runtime probes and
qualification rule remain unchanged. All caller versions share one exclusive
feasibility attempt and zero retries. This correction creates no new trial
allowance, fitness, selection or installation. The separately registered ordinary
evaluation still needs its actual six-check design review, seal, exact
running-ledger admission and native qualification.

## Evidence and consequences

The immutable terminal-history review contains 18 files, 131 workspace source
bindings and four authority bindings. Its directory digest is
`ad768940710a482dab28ca031194fef8e9bdd27ba84efbda953e411c649c2a51`.
Its original registration disposition is refused pending prospective review;
this decision preserves that finding. The review independently checked all 81
cumulative variant claims, the 585-variant/five-round limits, costs and unopened
private custody.
