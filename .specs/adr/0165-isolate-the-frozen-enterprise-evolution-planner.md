# ADR 0165: Isolate the frozen EnterpriseRAG evolution planner

## Status

Accepted for implementation and public rehearsal. Native study activation
requires an independent review, fresh validation registration and organizer
seal. This decision does not reopen E14 or E15.

## Context

[ADR 0164](0164-close-e15-after-independent-preparation-rejection.md) closed E15
without native execution. The interactive host identity could read the private
workspace, and the prospective runtime implemented qualification without the
complete catalog, joint replay and finalization lifecycle.

The remaining two public first measurements also need new task versions. Their
verifiers froze the original complete skill file map while permitting only a
retrieval-profile change. They would reject the corrected Entity Graph and
Ensemble implementations before measuring retrieval quality. Changing those
sealed tasks in place would invalidate their original evidence.

## Decision

The sole adaptive authority is a deterministic, digest-frozen planner in an
unprivileged Linux container. Its only input after the public plan is an ordered
batch of owner-authenticated development observations. It cannot access host
files, network sockets, sibling processes, private tasks, traces, or caches.
Kernel restrictions are installed before loading the planner or reading input.

The host remains a trusted execution broker and independent validation
authority. It resolves only closed, precommitted operations to native Harbor
jobs and official realizer commands. It must not supply new hypotheses,
alternative rankings, arbitrary commands, model messages, or adaptive human
choices after the public policy is frozen. A malicious privileged host remains
outside the protection offered by this boundary.

The inherited six completed family catalogs stay closed. Entity Graph and
Ensemble retain their finite construction catalogs, five-round ceiling,
cumulative nontransferable proposal caps and three-consecutive-evaluable-miss
rule. A strict improvement resets the miss counter; duplicates consume neither
an attempt nor a miss. An execution or qualification failure terminates the
current study rather than becoming a quality miss or automatic retry.

Both unconsumed corrected implementation identities establish prospective
references. Their first scores do not represent gains against the failed E14
implementations. Each subsequent profile mutation has an official realizer
lineage and a native owner archive. Realizer tree digests and Harbor skill
digests retain their different encodings; the broker explicitly binds both
through the original native record and exact staged package.

Public tasks receive append-only versions with exact implementation hashes.
The transformation changes `skill_files` and `imported_candidate_modules` in
the verifier contract, plus the two executor Compose configurations. Questions,
record identities, routes, scalar scoring, verifier code and resource limits
remain unchanged.

Independent inspection found that Harbor 0.18.0 gives the agent a writable
bind of its verifier results directory even with separate verification. A
digest-bound, process-local wrapper replaces only that agent mount with a
private tmpfs. The separate verifier retains its original results bind. Both
public and private workers require the same wrapper before loading the native
owner, verify the installed Harbor source, and reject other verification modes.
No installed Harbor files are modified. This public-code finding is not evidence
that a previous candidate exploited the shared mount.

Task containers use a read-only root, no capabilities, no privilege escalation,
private IPC, disabled network, a process cap and no Docker log archive. Each
gets a fresh anonymous disk volume for `/workspace`; generated knowledge must
not consume the memory budget through tmpfs. Small writable paths support native
skill installation and caches. The verifier also receives a writable artifact
transfer path. Native stop removes each container and its private volume.
Actual executor probes verify uploads, subprocess execution, artifact transfer,
feedback isolation and volume cleanup before registration.

After all open catalogs stop, two all-family development arms must reproduce
every retained family score. The planner emits one exact selection and exits.
The broker closes its input, records the exit and removes its container before
freezing the candidate and running two all-500 comparison arms. No comparison
or validation information is returned to a live optimizer. A changed candidate
then receives one independently administered private gate: native qualification,
strict aggregate gain, and a nonnegative paired mean within each of eight
families, each represented by two private groups. Private group regressions
are allowed only when these family and aggregate requirements still pass.

One OS-backed authority lease covers admission, allocation, native execution,
qualification and finalization. Each identity is durably consumed before its
side effect. Existing journals cannot be reopened by an ordinary launch.
Recalculation and private acceptance write outside the recorded development
evidence trees. Private acceptance uses an exact aggregate-only response schema.

## Consequences

The implementation can complete the requested finite search without giving an
interactive optimizer access to sealed validation. It does not claim that every
possible future evolution strategy has been exhausted. Native Harbor remains
the scorer, provenance checker and Pareto archive owner; the new modules
provide only the frozen orchestration policy and execution boundary.

The 120-question development sample and final 500-question comparison use
6,000 complete documents. Their retrieval results are internal comparisons,
not an official full-corpus answer-quality leaderboard position. Raw data,
native traces, private artifacts and generated knowledge remain ignored.

Synthetic container and lifecycle rehearsals are implementation evidence only.
They cannot substitute for independent dataset preparation, actual executor
isolation checks, native trial qualification or the final repository coverage
gate. See the [execution guide](../../docs/enterprise-isolated-evolution.md).
