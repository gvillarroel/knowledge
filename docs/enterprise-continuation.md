# Continuing EnterpriseRAG evolution after E7

E8 continues the authorized search across eight retrieval families after a
planned Windows update interrupted E7. The original study is terminal, with
66 completed native jobs, two incomplete originals and no private release.
Its [interruption report](../evaluations/reports/evolution/e7/interruption-001/README.md)
preserves the observed evidence. [ADR 0130](../.specs/adr/0130-continue-interrupted-enterprise-search-prospectively.md)
defines the new study boundary; the [E8 overview](../evaluations/reports/evolution/e8/README.md)
owns current execution status.

E8 subsequently exposed a native Compose process-classification gap. Entity
Graph and Ensemble were refused before any native trial; the
[independent diagnosis](../evaluations/reports/evolution/e8/dispatch-control-001/README.md)
and [ADR 0131](../.specs/adr/0131-correct-sealed-enterprise-admission-prospectively.md)
preserve the exact evidence and prospective correction boundary. The current
sealed controller continues independent lanes. Completed artifact-only reports
remain permissible after source verification; they do not authorize new jobs.

The separate [prospective scope helper](../evaluations/enterprise_execution_scope.py)
recognizes native Compose CLI/plugin forms and binds exceptions to declared
absolute host roots. Its caller must still verify source aliases, process
ownership, all historical ledgers and current-study mounts. It has no runtime
inventory, reservation or dispatch interface and is not loaded by E8.

## Execution order

The native Pareto owner revalidates the 66 exact completed E7 job/skill mappings
as historical development. Each family gets a new generation-zero archive with
its factual original sources; no job is rerun and old archives are not relabeled
as a preceding generation of a new search. Historical success, failures, exposure
and resource use remain visible.

Measure the four previously unstarted baselines first: Turso, Graphify, Entity
Graph and Ensemble, with two workers. Then evolve their candidates and continue
Classical and Adaptive. Legacy and Embeddings retain their already completed
searches. One family's failure stops that lane while other independent lanes
continue. An unavailable baseline cannot authorize candidate selection.

Reconstruct the original profile history, incumbents, counters and catalog
rounds. Strict qualified weighted nDCG@10 gains reset the miss counter; three
consecutive evaluable non-improvements move to another mechanism. Exact
duplicates consume no trial. Repeat improving rounds, with the inherited maximum
of five. The original 585-variant ceiling counts the 64 already started variants,
leaving at most 521 additional trials; the family-specific inherited caps apply
before every dispatch.

Classical023 and Adaptive019 remain unavailable. Their complete profile digests
are permanently reserved against new dispatch. Skipping them assigns no score,
miss or reset. A terminal round in those lanes must disclose the missing
hypothesis; it is not a fully measured E7 plateau. No original job, descriptor,
candidate package or earlier report is rewritten.

## Matched execution and acceptance

Retain the original 120-question, 112-eligible, 6,000-document development
contract and all 18 native routes. Construction and consultation remain separate
treatments. All original task paths, development/joint/private adapters, attempts,
hardware quotas and retry settings remain unchanged. A native preflight checks
the exact job signatures before execution. Timing across the host restart is
descriptive; exact joint replay must reproduce the retained quality scores.

Only the paired all-500 jobs use a new native execution profile:
`agents.override_timeout_sec=10800` and a final adapter whose actual execution
limit is also 10,800 seconds. Harbor 0.18.0 applies this override before the
inherited 3,600-second task default. Both baseline and frozen candidate use the
same final profile. Builder subprocesses retain their 2,400-second limit because
the corpus size has not changed. This is a prospective feasibility choice based
on published development timing, not an observed final result or speed gain.

The independent curator binds terminal E7 and the six earlier histories in a
new exclusive reservation. Only exact declared read-only model and verifier-test
mounts are permitted from history; whole workspaces, old jobs and optimizer
memory remain outside executor mounts. Native tasks and the still-unopened
private portfolio receive a fresh review and design seal before new trials.

All eight terminal family selections must replay jointly and reproduce their
scores before one merged bundle is frozen. Recalculate both arms on all 500
public questions, then release the same two-source private portfolio once.
Qualification, exact provenance and nonnegative mean paired gain for every
family remain mandatory for accepting the whole bundle. No private result can
change a profile, choose a replacement family or reopen evolution.

## Artifacts and checks

[Execution sources](../evaluations/enterprise-continuation/README.md) are tracked;
datasets, historical manifests, native jobs, candidate packages and private
reviews remain under ignored `tmp/e7/` and `tmp/e8/`. Use append-only paths.
The final publisher must identify historical versus new opportunities and retain
the unavailable hypotheses alongside family, route, category, application,
dataset and cost/time/quality reports. Installing an accepted package requires
an exact digest and a separate installation receipt.

After the complete native sequence, use
`python evaluations/publish_enterprise_continuation.py --output <new-report-directory>`.
The publisher replays cumulative development decisions and explicit unavailable
bindings before collecting the sixteen final native trials. It validates the
same eighteen routes, all 500 question positions and 470 eligible cases in each
arm. Its historical job totals count completed originals once; incomplete
original runtime remains unavailable. Missing final evidence prevents publication.

During active development, publish a completed family prefix with
`python evaluations/publish_enterprise_family_progress.py --family <family> --generation <completed-generation> --normalized-report <native-report>/final-report.json --output <new-report-directory>`.
First produce and inspect the native `harbor-run-results` comparison for the exact
baseline, previous incumbent and observed candidate, in that order with duplicate
references removed. Use `--compare --pass-threshold 0.8` and a new output path.
The prefix publisher requires that exact locked native comparison, replays all
preceding outcomes and inherited exclusions, and checks every route's weighted
case aggregates. Its family, application/category, route and CTA pages distinguish
gain over baseline from gain over the actual previous incumbent. An intermediate
report cannot freeze, promote or install a candidate, reopen a stage, or replace
the final all-eight report.

The prefix publisher verifies every frozen source group and the maintained
organizer's deep source/ledger state without invoking live dispatch admission.
It records that artifact-only scope in the aggregate. Development must still be
running and private gates unopened. The
[first Turso candidate report](../evaluations/reports/evolution/e8/turso-progress-001/README.md)
exercises this path with a complete, locked native baseline/candidate comparison.

Run the focused continuation/sweep tests after source changes and the repository
coverage gate before implementation closure. Sealed inputs are immutable; a
later implementation change requires a separately reviewed version rather than
editing the live controls. These deterministic retrieval trials have no answer
Overall score or official public rank. The
[full-corpus Classical/Luna report](enterprise-classical-full-corpus.md) is separate.
