# Public task bindings for all eight retrieval strategies

The complete reference package contains the fixed Graphify builder even when
another retrieval family is under evaluation. All sixteen public task contracts
therefore need to recognize that exact file before a later consultation study
can use the revised reference. This preparation covers Adaptive, Classical,
Embeddings, Ensemble, Entity Graph, Graphify, Legacy and Turso.

Each append-only task version changes one expected builder-file digest in
`tests/contract.json`. The remaining seven files retain their exact bytes, and
every other parsed contract value is unchanged. The full expected package
matches the sealed 252-file candidate. Only the retrieval profile remains mutable;
the builder is bound to its exact fixed bytes.

| Public workload | Families / task roots | Questions per family task | Source documents | Intended role |
| --- | ---: | ---: | ---: | --- |
| Existing stratified subset | 8 / 8 | 120 | 6,000 | Development under inherited history and cumulative limits |
| Existing all-question workload | 8 / 8 | 500 | 6,000 | Paired retrospective recalculation after one bundle is frozen |

These are the same exposed public workloads. The all-question set overlaps the
development subset; it cannot serve as independent validation. A new directory,
contract digest or native checksum creates no new independent semantic family.
The original role-specific weighting and block assignments remain intact.
No private tasks were read or changed during this preparation.

Two materializations, under different roots and reversed source enumeration,
produce identical task trees. Harbor 0.18.0 successfully parses all sixteen
versions and preserves their native task configuration. Its content-hash and
trial-checksum calculations distinguish each revised task from its original and
agree across the reproduced trees. Native packaging includes all eight expected
files in every task. The Graphify development task also matches the separately
prepared fixed feasibility task exactly.

The single fixed Graphify feasibility trial must qualify before these task
versions can support a consultation reference. A later study must retain all
consumed attempts, unavailable hypotheses, counters and rounds; register its
actual task bytes and independent validation before evolution; qualify every
actual retained package; replay all eight selections jointly; and complete the
paired all-500 comparison followed by the one-way whole-bundle acceptance gate.
These authoring checks do not replace any native qualification or oracle gate.
The duplicate `reproduction` tree is authoring evidence and must be excluded
from any registered task root.
The task configuration retains its original limits; any future all-500 execution
override still belongs to the separately frozen execution protocol.

The first authoring preflight refused a reference to the earlier control file
before writing any task. Its original source and refusal are preserved. The
corrected authoring script binds the independently reviewed active control
version. Neither preflight consumed a native attempt or changed a source task.
Raw tasks, repeated materializations and detailed manifests remain ignored.
