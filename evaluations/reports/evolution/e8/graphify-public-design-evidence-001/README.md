# Graphify: reviewed public design preparation

An independent curator supports all six static preparation checks for the one
fixed public Graphify feasibility trial. The review binds 169 sources, reuses
eight completed review directories, verifies sixteen stored semantic negative
results and adds 29 bounded synthetic checks of the unchanged task verifier.
It performs no native job, builder, model, retrieval query or container run.

| Design check | Supported evidence | Practical limit |
| --- | --- | --- |
| Provenance and exposure | Exact task, package, protocol and earlier review bindings | The EnterpriseRAG development workload is already exposed |
| Group isolation | One conservatively connected public corpus/task family | No new independent groups; the subset overlaps the all-500 cohort |
| Task surfaces | Explicit output carrier, formatting and renamed-identity checks; prior layout parity | No cross-split balance or paraphrase-quality claim |
| Verifier quality | Valid alternatives, meaningful counterfactuals, malformed/stale outputs and reward-file manipulation | The actual complete build and submission remain unmeasured |
| Coverage and power | All 120 requests, 112 eligible requests, weight 470 and 6,000 records | One attempt tests this fixed execution; no generalization or paired effect estimate |
| Access isolation | Prior direct image/resource probes and the reviewed complete native caller | Actual Harbor-created mounts, staging and submission must still be observed |

The new synthetic checks use invented records and requests. They exercise
metric arithmetic, directional ranking changes, valid alternative outputs,
identity and file drift, declared output locations and overwriting a planted
reward. They do not score an EnterpriseRAG question. The previously completed
fixture, environment and caller suites were not rerun.

Two observed limitations remain explicit. Otherwise valid empty rankings receive
zero retrieval rewards and evidence integrity one: the fixed feasibility protocol
requires genuine completed construction and finite scores, with no positive
quality cutoff. Also, pure scoring cannot authenticate self-reported construction.
The exact deterministic bridge and mandatory native source, staging, runtime,
submission and terminal checks remain necessary. Synthetic scorer acceptance is
not proof that a build happened.

The reusable review template deliberately has no registered dataset/task digests
and no final pass declarations. After E8 actually finishes, independent review
must bind complete terminal history, consumed resources, exclusions, counters,
rounds and private non-consumption. The organizer must register the exact task,
bind its actual lock in a fresh final review and seal the design. Separate
admission and all actual native checkpoints are still required.

The frozen allocation remains one candidate trial and zero retries, shared across
superseded proposals. Keep the admitted running-stage ledger unchanged through
the run, maintained report, report read and qualification; append outcome evidence
and close the stage afterward. Any required failure ends this fixed design.

This preparation gives no retrieval gain, original-versus-new native speed ratio,
baseline equivalence, independent acceptance or installed improvement. A qualified
builder could support a separately sealed consultation study. The all-eight joint
replay, paired all-500 comparison and whole-bundle one-way acceptance remain due.
