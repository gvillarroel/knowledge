# Native retrieval evolution: infrastructure evidence

[Evolution studies](README.md) · [Operating guide](../../../docs/retrieval-profile-evolution.md)

The `20260906-r2` campaign stopped before it produced any valid fitness score.
Its incomplete native Harbor baseline job recorded two completed agent outcomes,
two artifact-collection errors, one running cell and 29 pending cells. The two
terminal records have no verifier result. No mutation candidate was evaluated
and the independent validation portfolio was never released.

Harbor 0.18.0 raised `OSError: [Errno 5]` while inspecting its mounted
`artifacts/logs/artifacts` directory on Windows/WSL DrvFS. Both recorded agents
had completed construction and retrieval before this failure. The native job,
exception artifacts, original frozen orchestration bytes and an append-only
stop receipt remain in the ignored original campaign directory. Its organizer
evolution, validation and publication stages were stopped. These artifacts must
not be presented as scored results or merged into a replacement job.

The installed external-failure recovery contract did not apply: its supported
verifier-only path requires a Pi trace and a sealed selective-retry journal;
this incomplete deterministic-agent root has neither. No effective job was
fabricated and no verifier was run against the failed campaign's outputs.

An independent tester completed a separate synthetic check with two concurrent
trials, the exact runtime and baseline, the production cleanup configuration,
and short output paths. Both trials completed all five verifier measures with
value `1.0`, zero errors, zero retries, zero instruction-model calls and zero
provider charge. Actual agent execution overlapped for **3.837891 seconds**.
All four live containers were observed with networking disabled and loopback
only. The separate verifiers alone mounted their tests read-only; production
cleanup removed all four containers. Both short mounted artifact directories
remained readable after cleanup.

This supports a short-path infrastructure mitigation. It does not prove path
length was the sole cause of the original failure, recover the aborted job,
or establish retrieval performance on real datasets.

The subsequent `knowledge-retrieval-e3` study used ignored `tmp/e3/` output paths.
Its six-check independent review verified exact byte equivalence for the
baseline, all 48 task definitions, source inputs and archives, annotations,
seed, authoring artifacts, reference cores and quality receipts. The runtime,
model, four hypotheses, selection criteria and unused validation portfolio
remain unchanged. Job templates differ only by workspace prefix. New design
commitments record this infrastructure lineage explicitly.

That campaign also stopped without a valid retrieval score. Its final native
counters show six terminal errors, zero running trials, and 26 pending trials:
four `RewardFileNotFoundError` results, one agent `RuntimeError`, and one
cancelled trial. The first four verifiers could not execute the generated shell
entrypoint because the Windows writer had emitted CRLF after its shebang.
The source generator now requests explicit LF. An automated regression invokes
the actual generator and reproduced the original four carriage-return bytes.
An independent two-task native smoke then completed successfully using the
corrected generated files without post-generation rewriting.

The agent `RuntimeError` exposed a separate real Graphify construction defect.
An empty Markdown heading retained an ID derived from a random temporary path.
Two independent full build pairs, including one with a fixed Python hash seed,
changed only the graph and its index while their authoritative cores matched.
This is a semantic determinism failure, not an eligible external retry.

The source-generic correction preserves the heading as a distinct node, binds
its identity to the relative source and location, and remaps both endpoints of
its links. It updates the canonical builder and its exact integrated copy.
Four actual synthetic production builds, covering both physical layouts and
two output roots per layout, passed their production validators and produced
identical graph bytes across all four outputs. The examples include empty and
punctuation-only headings plus relative references. These checks establish
correctness, not retrieval improvement.

The repaired production builder subsequently completed two full constructions
and their production validators on the same exposed development corpus. All
30 output files were byte-identical between repeats; its 28 authoritative core
files also matched the original constructor's output exactly. The evaluated
package and source files remained unchanged.

The final independent native smoke executed all eight actual generated family
tasks from a frozen copy of the corrected package. It completed eight trials,
18 declared routes and 54 synthetic route-query correctness checks, with zero
errors, retries or model calls. Both repeated construction and evidence integrity
passed in every family. The observed peak agent concurrency was two; all 16
containers were inspected with no networking and removed by production cleanup.
Only three self-authored manuals were used. Generated task and package bytes
remained unchanged. These are adapter correctness checks, not dataset rankings.

The `e4` preparation freezes this separately corrected baseline, regenerates
LF task entrypoints, and preserves the same unconsumed sources, seeds, model,
runtime, hypotheses and acceptance rules. It requires new baseline/task digests,
actual qualification receipts, and independent design review before evolution.
See [ADR 0118](../../../.specs/adr/0118-normalize-empty-graphify-heading-identities-before-profile-evolution.md).

The independent e4 review subsequently approved all six authoring checks and
verified the three current dataset locks and 48 regenerated tasks. It replayed
source/provenance and contract/entrypoint audits, checked the corrected full
Graphify artifact trees, and bound the exact eight-family native smoke package.
The organizer accepted the new design seal before candidate realization.

The e4 baseline then completed all 32 native trials with zero execution errors
and full evidence integrity. Its 72 route aggregates and 2,880 query-route
executions are retained in the [baseline diagnostic](e4/baseline-diagnostic/README.md).
The installed evolution owner rejected the declared/observed agent profile
before dispatching any candidate or producing an accepted archive: the custom
agent reported `skill-retrieval`, but its JobConfig left `name` null. These are
valid native diagnostic scores excluded from selection, unlike the unscored
r2 and e3 attempts. All downstream e4 stages were stopped; validation remained
sealed. Original results, locks, configs and the failure log are preserved.

An independent e5 qualification exercised the installed owner with the exact
synthetic Classical and Turso tasks, the unchanged baseline and a realizer-sealed
BM25 length-normalization candidate. Explicitly declaring the existing agent
name instantiated the same class, version and local model identity. The owner
completed both jobs and all four trials, advanced from baseline to candidate,
and produced a valid archive with two qualified candidate results. The reviewer
reloaded the native jobs through the owner and verified their archive records,
source/staging digests and native locks. All eight observed containers were
offline and removed by ordinary cleanup; errors, retries and model calls were
zero. Neither the installed controller nor the agent implementation changed.

This closes the configuration boundary described in
[ADR 0119](../../../.specs/adr/0119-declare-native-agent-identity-and-qualify-the-owning-controller.md).
It does not recover e4 or establish a retrieval improvement. The new e5 study
preserves the original source portfolio, seeds, runtime, model and hypotheses;
its own design seal and execution evidence must establish admissibility.

A separate neural forward pass then exercised the exact previously sealed
`neural-record` package on the unchanged synthetic Embeddings and Ensemble
tasks. Both native trials completed all six routes and 18 query-route checks
with zero errors, retries or instruction-model calls. Live read-only observations
captured both builds' indexes in both families: all four use local MiniLM
revision `1110a243fdf4706b3f48f1d95db1a4f5529b4d41`, preserve record chunking,
and bind to the final artifact hashes. Repeated builds were identical, model
bytes were unchanged, and no download occurred. All four observed containers
were offline and removed after ordinary cleanup. The installed owner accepted
the profiles and package/lock provenance through read-only canonical analysis.
This additional direct native job did not repeat the baseline or establish
another search archive; the preceding qualification exercised the full owner.

The independent e5 curator review approved all six maintained checks and the
organizer accepted its schema and gate coverage against three dataset locks and
48 task definitions. The reviewer replayed source/annotation, uniform-surface,
verifier and cross-group checks, verified all sixteen qualification bindings,
and confirmed no previous private-gate release. An additional read-only audit
of the installed local skill-injection path rejected all attempted writes,
subprocesses and network connections; none occurred. The unused remote skill
cache needs no configuration change for this frozen local-only pipeline. The
organizer sealed the exact protocol and final review directory before realizing
the four candidates. Native dry-run and doctor then passed before e5 execution.
