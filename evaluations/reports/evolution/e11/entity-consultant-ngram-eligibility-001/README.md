# Entity Graph consultant: exact n-gram eligibility transfer

The consultant candidate passed **seven software checks** and a **1,024-record
consultation-only runtime cell**. It preserves the complete builder, exact
extraction results and retained deep-validation response. Its new native
EnterpriseRAG first measurement remains **unassigned**; no new retrieval score
or canonical skill promotion is claimed.

## What changed

Only the consultant's `_candidate_statistics` body changed. It now counts
disallowed tokens once and checks two prefix-count boundaries before allocating
an n-gram tuple. The implementation is identical to the frozen builder module.
Eligible-window order, excluded aliases, counts, frequencies, score arithmetic,
rounding, tie ordering, routes and full independent validation are preserved.
The other 251 package files are unchanged.

The seven checks include 4,080 exact comparisons against the parent and an
independent occurrence-counting oracle, including 1,306 nonempty comparisons
and two hand-counted oracles. Four schema/layout integration cells passed
192 child commands: 16 builds, 16 independent validations, 32 nonempty query
pairs, eight deep inspections, 40 builder and 40 consultant corruption
rejections, and eight existing-output rejections. These are software cases,
not independent EnterpriseRAG benchmark tasks. [Contract coverage](groups.md).

On the declared 1,968-token operation-count cell, stopword membership checks
fell from 28,704 to 1,968 and digit checks from 28,512 to 1,952, with equal
results. This establishes less repeated predicate work, not a native speedup.

## Pinned runtime and preserved refusal

The first runtime preparation refused before starting the consultant because
the pinned image contained a `/dataset` directory. A subsequent metadata-only
probe counted two entries without reading their names or contents. The corrected
control masks that directory with an empty read-only mount. The original
refusal, exact source change and both terminal observations remain preserved.

The corrected control ran the candidate once in Python 3.12.13, with 2 CPU,
6 GiB, network disabled and a 300-second child limit. Only the consultant and
the retained processed snapshot were supplied as skill/data inputs. No builder
or parent was executed. Deep rederivation completed in **8.909 seconds**,
returned exactly the retained JSON response, and preserved all 19 snapshot
files. The mounted snapshot contains 1,024 public synthetic JSON records.

This single cProfile observation includes overhead. The snapshot uses a
read-only host bind mount, so historical timings with other storage placement
are not a paired comparison. It establishes compatibility, not the 6,000-document
resource fit, retrieval quality or a causal performance gain. [CTA](cta.md).
