## Exact change and verification

Two builder files transfer existing Ensemble state-lifetime boundaries into
the Entity extraction candidate. The public semantic validator retains its
signature and original docstring. All 250 other files, including the whole
consultant and existing mention/extraction algorithms, remain unchanged.
The [decision record](../../../../../.specs/adr/0145-transfer-builder-state-lifetimes-to-entity-graph.md)
describes the scope and limitations; the [aggregate](aggregate.json) binds the
parent, donor, candidate, software checks and original runtime evidence.

Four schema/layout cells passed 192 CLI commands: 16 complete builds,
16 independent validations, 32 nonempty paired query responses across all
four routes, eight deep inspections, 80 corruption rejections across builder
and consultant, and eight overwrite rejections. Four paired injected failures
also preserved error results and left no partial publication or candidate.

The lifetime fixture observed four parent-generated RDF graphs still live at
the first independent validation entry, versus zero for the candidate. The
candidate released reconstructed graphs before later SHACL checks, its
persisted projection mapping before rederivation, and five parsed graphs plus
one SHACL result graph before semantic validation returned. The projection
probe wraps only the outer mapping; it does not copy the arrays. Automatic
garbage collection remained enabled. These are lifetime observations, not
native peak-memory or latency measurements.

The separate pinned-runtime cell processed the same 1,024 synthetic JSON
records, preserved all 19 retained reference files, and passed standalone
validation and deep consultation. The reference was read, not executed again.
Its three timed commands include profiling overhead and do not supply a paired
causal speedup estimate. See [CTA](cta.md) and [coverage by contract](groups.md).
